# Parent documents, personal portraits and required updates

This change keeps parent report-card previews on the same canonical official renderer as administration and makes the issuer filename available through the shared preview. Parent performance is organized into six accessible tabs rather than a vertical stack. Kitchen consumer totals appear before the daily menu; the activity log has its own bounded scrolling area.

Certificate narrative is shared between browser prints and email attachments, in French and English. It uses verified identity, enrollment and issue-date data and does not invent a birthplace or good-conduct statement. The optional digital signature/seal setting does not remove the QR or the authority name. Super Administration can set the current principal name and a separate override for report cards, transcripts, attendance, completion and admission certificates in Settings / Official document authorities. Updates are audited and apply to future editions; archived documents are preserved. Report-card Edit/Polish authority settings remain compatible.

Personal dashboard portraits are read through authenticated, account-bound gateways. Official registry portraits are never updated by this mechanism. EduPay personal photo changes use the same separate Nexus personal-avatar field. Private browser caches are account- and application-scoped; failed connectivity keeps the last valid portrait. A late response cannot replace a different account's portrait.

The shared client runtime implements centered, required updates for all eleven application identities, including both election PWAs. There is no Later dismissal. Active fetch/XHR writes block reload; a bounded save-work interval and explicit draft protection precede the update. Durable offline payment queues survive reload. Version checks require the owning app and scope and never treat a network failure as proof of an update. Existing running clients acquire the new runtime when they next load the new release.

Nexus no longer intercepts Jury navigation/API requests. Sentinel and the election workers exclude private API and sibling-app paths. Jury loads its workspace pages lazily and prepares a short-lived openerless launch link in advance, preserving user-initiated PWA navigation. Native link capture still depends on installation and the browser/OS link-handling preference; a website cannot override that preference.

Validation: fifteen production component builds; TypeScript/static build and twenty election tests; fourteen affected backend tests; required-update browser coverage for eleven identities, dirty forms, active fetch/XHR writes, durable offline queues and version isolation; personal portrait browser tests (offline reload, account switch, optional storage); twenty-one worker isolation paths; API authority/portrait tests in a synthetic database; eighteen layout/theme checks across 390, 768 and 1440 px; rendered French/English certificate fixtures. Private fixtures, logs, tokens and screenshots stay outside Git.

Runtime copies and certificate wording are verified by ops/client-runtime/sync.mjs --check. The explicit deployment scope is Nexus API/Web, Jury Web, Kitchen API/Web, Sentinel API/Web, Eduplanner Web, Academy, EduPay API/Web, Savanex API/Web and EduSync API/Web. Elections publish through their separate static repository. No database schema, calendar, grades, financial calculation, authentication password or official student photo is changed.
